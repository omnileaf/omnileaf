# Content policy

Omnileaf is a reader. These rules keep the project, its code and its infrastructure clear of the content people read with it. They apply to code, tests, docs, issues, pull requests and anything the project publishes.

## The app

- The app ships with no content and no content sources. It reads local files, OPDS catalogs and self-hosted servers that the user sets up. Code that targets a specific website doesn't belong in this repository.
- No circumvention of DRM or other copy protection. Protected books and files are detected and refused with a neutral message.
- No API keys, client IDs or other secrets taken from other apps or services. Integrations use credentials registered for Omnileaf.
- Content stays on the user's device. The app fetches it directly from the source the user configured. Downloads, preloading and caching all happen on the device.

## Servers

Any server run for Omnileaf, such as the sync service, handles data only: reading progress, library metadata and settings. It never stores, caches or proxies pages, images or books.

There is one exception. So that a cover someone chose and their profile picture look the same on every device, the sync service may store a person's own chosen cover images and profile pictures, end-to-end encrypted, within a small allowance per account. It can't see them, and it stores nothing else of the kind.

## Tests, docs and screenshots

- Test fixtures are generated by the project's own tools. Never commit real comics, books, covers or series names.
- Screenshots show the generated sample library only.
- Examples use reserved example domains such as `example.com` and `*.test`, never real sites.

## Branding

Omnileaf's name, icon and branding use no third-party trademarks.

## Issues and pull requests

Don't attach or link to copyrighted material, and don't ask for support for specific websites. Issues and pull requests that do are closed.
